# MarketPulse UI audit · November 20, 2026

The most consequential defect was in privacy mode. A manually valued asset can have one unit, so showing its unit price also shows its entire value. In the fictional ledger, the sculpture’s price was 65,432.10 CAD. After the fix, the price, quantity, value and gain all displayed •••• while the public XEQT.TO quote remained visible.

The audit covered the nine macOS workspaces, transaction and import sheets, Settings, menu bar implementation, and eight terminal workspaces. Native checks used the QA bundle and fictional ledgers. Terminal checks used Textual’s headless pilot and a fake quote provider. The only open issue was optional encryption, which the maintainer kept scheduled for later. There were no open pull requests. [Issue #25](https://github.com/BrendanH18/Marketpulse/issues/25)

## Findings and changes

| Area | What a user encountered | Change and evidence |
| --- | --- | --- |
| Privacy | Manual and accrued prices exposed asset values. Transaction hints, confirmations and tax details could reveal quantities. | Masked private prices and quantities across affected surfaces. Verified both the sculpture and GIC in native Holdings, and the masked AAPL disclosure in Tax. Terminal regressions cover a manual price in Holdings and Activity and the acquisition cost of a market-priced share. The Mac rejected a fictional oversell with “Check the transaction details and try again” in privacy mode. Enabling privacy from the scratch CLI while the rejected form remained open replaced “only 4 held” with the same private message. |
| Numeric input | In a terminal form, typing `1,5` could save 15. | The form and manual valuation prompt reject malformed grouping and non-finite numbers. Tests distinguish `1.5`, `1,234.50` and `1,5`. The Mac form continues to use the system locale. |
| Search | Searching Holdings for `iShares` silently emptied Activity. Terminal search missed text past the displayed column width. | Each native workspace remembers its own query. ⌘F focuses it, Escape clears it, and **Clear filters** resets the query and account. Activity matches dates and account names. A terminal test finds text beyond the visible end of a note. |
| Data entry | The native Save button could be disabled without an explanation. Errors from another operation could appear in the form. | An empty transaction requests an account, then the symbol, then a positive quantity. A duplicate-account error disappeared on Cancel. Selected rows expose editing actions. Return submits a Watch entry. |
| Small windows | At 80×24, the account pane squeezed the tax report and a form could scroll its own validation error out of reach. Long native panels could put actions below the display. | Compact Tax stacks the panes. The dashboard opens with the summary tiles visible and focus on its outer scroll area. Page Down scrolls and Home returns to the tiles. Validation brings the error into view. An AppKit sizing check measured 2,904 points of panel content in a 240-point scroll viewport, while a two-row panel measured 88 points. |
| Recovery | A failed native first load suggested reinstalling the CLI. A terminal Tax or Income worker failure could end the interaction without a useful recovery action. | After an injected backend failure, **Try again** restored the portfolio. The backend launch error includes guidance for a configured executable. Terminal worker errors offer **r** to retry. A late failure from a superseded Tax or Income request leaves the successful retry visible. While a valuation was paused, Income retained historical totals and cleared the one-share estimate. Reopening Income after a failed valuation preserved the retry hint. Retrying displayed the two-share estimate. A terminal save now reads the account name before committing so a failed lookup can be retried safely. |

The 980-point minimum portfolio width remains a limitation for side-by-side windows. Reducing it safely requires adapting the Overview cards, filter bars and fixed-width tables together. The audit also identified broader storage-write error handling as a separate engineering task. The current changes cover transaction saving and the portfolio, tax and income loading paths.
